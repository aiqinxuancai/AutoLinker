# 删除程序集和类

`delete_file` 与 `add_new_file` 共用 IDE 主线程工具调度、交互审批、写入前工程备份和异步完整镜像刷新流程。内部 AI 与外部 MCP 均可调用。

先调用 `read_real_file` 读取目标，随后传入其 `code_hash`：

```json
{
  "name": "delete_file",
  "arguments": {
    "file_path": "src/待删除程序集.txt",
    "expected_base_hash": "read_real_file 返回的 code_hash"
  }
}
```

删除普通程序集或类时，其成员及全部子程序一起删除。其他页面中的引用不自动改写，工程不自动保存。窗口绑定程序集、窗口 XML、固定表和导入模块文件不支持此入口。

成功结果包含 `deleted: true`、`verified: true` 和 `workspace_mirror_refreshed: true`。源码哈希变化、目标不存在或目标不受支持时返回错误。若删除已发生但镜像发布失败，返回 `deleted: true` 与错误，调用方应刷新镜像，不能盲目重试删除。

## 原生路径

当前使用程序树的原生删除功能号 `0x82020017`，不再通过插件解析程序集索引调用 `0x0202001A`，也不再要求 e5.95 的 PE 时间戳、映像大小或内部入口签名。

- 在 IDE 主线程中，通过标准 TreeView 消息定位“程序数据”树，按节点标识和完整名称唯一匹配目标；只接受程序集/类节点。
- 窗口绑定来自工程镜像 `_meta.json` 的 `windowBindings`，缺失或格式错误时拒绝删除；类类型来自导出的 `.程序集` 声明的基类字段，不根据中文名称、生命周期函数或图标猜测。普通类的 `<对象>` 和派生类的基类名称均属于类。
- 选中目标后重新核对节点标识、名称、选区及工程/镜像代次，再查询命令可用性并通过 `IDEFacade::RunFunction`（`NES_RUN_FUNC`）提交一次命令，不抢焦点、不打开目标编辑器。
- 在 e5.95 中，经 IDA 确认程序树分派器会把程序集节点转交 `0x0202001A`，由 IDE 自己解析索引、关闭编辑页、记录撤销数据、删除成员及子程序并刷新程序树。插件不再读取编辑器和程序集对象的固定偏移。
- `0x82020017` 仍是逆向确认的内部功能号，不是公开 SDK 的稳定承诺；`FN_IS_FUNC_ENABLED` 对未知命令可能返回可用，故可用性查询与调用返回值都不能作为删除成功或跨版本兼容的依据。命令提交后不尝试其他删除入口。

程序树刷新是异步的，不能在删除函数返回后立即据旧树节点判断失败。当前实现清空真实页缓存，提交完整镜像刷新，在同一工具事务的刷新完成阶段检查目标从程序树和镜像消失，且其余程序树项目仍在；此阶段不会再次调用删除。

## 回归测试

使用 `eproj` 中工程的临时副本，加载新编译的 `AutoLinker.fne` 并打开 IDE 主窗口后运行：

```powershell
python scripts/test_delete_program_unit.py --project <临时工程.e> --output <结果目录> --endpoint http://127.0.0.1:19207/mcp
```

若旧版 IDE 会话占据网关，可通过 `list_instances` 找到测试实例的 `backend_endpoint`，直接传入。测试会改动临时工程的内存状态，禁止指定原工程。

测试覆盖中文程序集和类、误导性名称的类型识别、成员及多个子程序、源码变更后的哈希拒绝、窗口绑定元数据缺失时拒绝删除、非当前页删除、重复删除、同名重建、固定表及越界路径拒绝、原源码逐字节保持、磁盘工程未保存，以及删除后编译。成功删除必须包含 `native_delete_selected_program_item|command=0x82020017` 路径标记。`e-window-exe-full.e` 还覆盖窗口绑定程序集保护。

## 2026-10-11 验证

先在独立试验构建中保留旧版保护检查，仅将实际调用换成选中节点后的 `0x82020017`；e5.95 窗口工程副本的 12 项回归全部通过，包括普通程序集、类、非当前页删除、窗口保护、磁盘工程不变和删除后编译。确认入口可用后，再替换正式实现并去掉固定内部地址及对象偏移。

正式实现的最终回归共 27 项通过（控制台工程 13 项、窗口工程 14 项），两个工程均在删除后编译成功，原有源码逐字节保持且磁盘工程未保存。`fne_release|Win32` 构建为 0 警告、0 错误。结构化结果与产物 SHA-256 见 `docs/program-unit-deletion-validation.json`。

正式实现使用隔离的 IDE 安装目录和 `eproj` 工程副本测试，不覆盖正在使用的正式 IDE 插件。5.71 也已启动测试，但首次 `refresh_workspace_mirror` 在现有工程序列化路径中返回 `restore current serializer source path failed`（`restore_call=0|restore_verify=1`），未进入删除阶段。因此只能确认删除入口不再硬编码 5.95 限制，不能宣称完整 MCP 删除工具已经兼容 5.71。

现有 `add_new_file` 整页写入会丢失指定的基类声明并回滚，不能用该入口准备派生类夹具。本次未修改新增功能，派生类删除仍未完成实测。
