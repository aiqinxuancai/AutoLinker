# 二进制 .e 工程在当前进程重新加载的调查与实测

调查日期：2026-10-09。结论：**可实现，无需重启 IDE；应调用完整工程加载链，并在 IDE 主线程执行。** 本次完成逆向与隔离实例测试，未把内部调用接入正式插件，也未实现备份恢复按钮。

## 分析对象与地址约定

- IDE：`C:/Users/aiqin/OneDrive/e5.6/e5.95.exe`，x86，文件大小 3,338,240 字节。
- SHA-256：`368CBBD323D2C5BC00F0C072B116333F75339FC0742E238D3E5E6FF17ABE1409`。
- IDA 数据库：上述文件对应的 `e5.95.exe.i64`；MCP 端口 `13337`。
- 下文为 IDA VA，image base 为 `0x400000`。运行时地址 = EXE 模块基址 + (IDA VA - `0x400000`)。不能把这些 VA 直接当作 RVA。
- 仅验证此版本；函数名部分为按行为整理的语义名称。现有背景见 [IDE 内部对象笔记](ida-eide-internals-notes.md)。

## 两种入口的实际区别

现有 `IDEFacade::OpenFile` → `RunOpenFile2` → `FN_OPEN_FILE2 (0x03010008)`，通过 `NES_RUN_FUNC (2)` 调用公开功能。该命令会检查路径、其他实例占用以及未保存状态；目标路径等于当前工程路径时，路径检查会跳过真正加载。返回真只说明命令被处理，不代表工程内容已更新。

内部 `0x46B310` 是完整工程打开入口，能够跳过上述同路径判定。实测替换同一路径文件后调用它，当前 PID 不变，真实代码页更新为新内容。它会关闭旧视图、加载工程、重建数据和界面；不能只调用底层反序列化后就认为 IDE 已完成更新。

| IDA VA / 偏移 | 含义与证据 |
| --- | --- |
| `0x6756E0` | 全局文档/控制对象**本体地址**，不是存放对象指针的槽。`0x401E55` 使用 `mov ecx, offset ...`；实测对象地址 `006756E0`。 |
| 文档对象 + `0xC0` | 工程序列化对象。 |
| 文档对象 + `0x3FC` | 当前路径 CString，相当于序列化对象 + `0x33C`。仅用于调查读取，不能仅修改它就宣称完成路径恢复。 |
| `0x46A390` | 文档功能分发入口。 |
| `0x47AED0` | 文件功能处理，包含 `FN_OPEN_FILE2`。 |
| `0x46B220` | 路径检查；同路径和其他实例占用会影响后续打开。 |
| `0x46A5D0` | 未保存修改的确认。 |
| `0x46B310` | 完整工程打开/重新加载入口。 |
| `0x46B010` | 关闭/重置当前工程相关界面。 |
| `0x46B4D0` | 工程加载分发。 |
| `0x457490` | 扩展二进制文件加载。 |
| `0x45C4A0` | 从 archive 反序列化；入口即清理旧工程数据。 |
| `0x460CE0` | 重置工程状态。 |
| `0x46D0C0` | 加载后依赖、数据、路径、标题与界面的收尾处理；失败也会重置状态。 |
| `0x46D3C0` | 加载后进一步界面刷新。 |
| `0x460C80` / `0x460CB0` | 查询修改状态 / 标记已保存。 |
| `0x5BC48F` / `0x5BC421` | IDE 自身 CStringA 构造 / 析构。 |

普通非空 .e 文件的关键调用链：

```text
0x46B310(doc, &nativeCString, 0)
  → 0x46B010
  → 0x46B4D0 → 0x457490 → 0x45C4A0
  → 0x46D0C0 → 0x46D3C0
```

已有 `0x4570D0` 较底层文件加载函数，但其调用场景主要涉及模块/编译等流程；本次没有把它单独用于完整 IDE 恢复。

### 测试使用的调用约定

以下签名为此版本 x86 的实测 ABI，不是跨版本公开接口：

```cpp
using Dispatch = int(__thiscall*)(void* doc, unsigned cmd, int flags,
                                const char* path, void* extra);
// 0x46A390: (doc, 0x03010008, 15, path, nullptr)
using OpenProject = int(__thiscall*)(void* doc, void* nativeCString, int flag);
// 0x46B310: (doc, &nativeCString, 0)
```

路径参数必须使用 IDE 自身 CStringA ABI；测试调用 IDE 内部构造和析构，未直接传入插件所用 MFC 的 CString。只实测了 flag = 0，其他 flag 的语义与安全性未验证。测试路径是 ASCII，中文页名经 MCP UTF-8 传递；中文/长路径文件名兼容性不属于本次已验证范围。

## 实测方法和证据

启动专用 IDE PID `66824`，主线程 `59996`，打开 `.tmp/project-reload/baseline.e`（来自 `eproj/e-window-exe-full.e`）。全部载入操作发生在这个进程，没有通过重启实现更新，也未操作用户原有 IDE。

测试探针为单独编译的 x86 DLL/控制器，使用线程限定的 `WH_CALLWNDPROC` 在主线程调用。探针限制命令行包含 `project-reload`，检查分发入口、完整加载入口和 CString 构造入口的前 16 字节。该校验是实验保护，不代表已完成适合正式产品的版本兼容验证。

通过 MCP `edit_file` 修改真实代码页 `src/窗口程序集_启动窗口.txt`，再调用 `refresh_workspace_mirror(mode=full)`，复制 `project/.native_source.bin` 得到有效快照 A、B。没有直接篡改快照字节来构造正向样本。每次加载后重新导出完整镜像并读取真实代码页，核对代码 hash 和窗口事件索引。

| 用例 | 观察到的结果 | 耗时 |
| --- | --- | --- |
| 公开打开命令加载不同路径 A | 代码变为 ReloadMarkerA，成功 | 1,719 ms |

### 无效文件的负向实验

将 .e 二进制中的 Manufacturers 等长替换为 ReloadMarkerA，触发 IDE 报错“文件中的重要数据段[程序数据段]校验失败!”，原工程状态被清空。关闭专用测试进程的错误对话框后，通过完整加载入口重新加载 baseline 恢复。

这次模态错误造成探针超时，未获得完整调用报告，因此不记录它的函数返回值，也不把它算作自动回归通过项。它说明直接改字节会破坏数据段校验；恢复输入应当来自合法序列化快照，或来自正确处理格式和校验的生成器（后者本次未测试）。

## 接入正式备份恢复功能前需要补齐的工作

1. **事务和失败回滚。** 完整加载会先销毁旧状态，失败不会自动保留原工程。必须先通过现有进程内序列化捕获包括未保存内容的安全快照，确认写出成功后才切换，失败时重新加载安全快照。正向恢复安全快照已测；自动失败回滚机制未实现。
2. **原工程身份和修改状态。** flag = 0 会把当前路径切换成加载的快照路径，并将工程标为已保存。若产品语义是“将备份内容恢复到原工程”，应恢复原工程路径及相关标题/上下文，并标记有待保存的修改；这部分本次没有验证实现，不应直接让用户继续保存到 .BAK 下。
3. **同路径缓存和会话失效。** `AutoLinkerRuntime.cpp` 的 `HandleCurrentSourceFilePathChanged` 会清理序列化上下文与 PageCodeCache，并通知 AI 会话。同路径重载不会自然触发这个路径变化事件，必须显式处理。`WorkspaceMirror::InvalidateMirror` 只更新 generation；`ResetAndCleanup` 同时更新 generation 和 contextEpoch。旧对象指针、页 ID、镜像以及未完成请求不能继续引用旧工程。
4. **主线程与 AI 工具调度。** 工程切换应在主线程执行，与正在进行的 AI 编辑、读写、快照和镜像刷新协调，阻止旧请求结果写回新工程。测试没有覆盖并发 AI 调用。
5. **结果验证和兼容性。** 不能仅凭公开命令返回真判断成功；至少检查工程路径、代码/数据和镜像。正式封装要核验目标版本、对象和调用 ABI，覆盖缺失支持库、密码工程、损坏文件、中文路径等。不要把当前绝对地址无条件用于其他版本。

本次确认的是有效完整工程文件的同进程加载能力，不是增量热补丁，也不保证保留旧工程的撤销栈、光标、断点或调试状态。恢复功能后续已在独立设置页中接入，并通过单独的恢复/回滚报告验证；未执行恢复后工程编译/运行。调查探针已编译并执行。

收尾验证：专用测试进程 PID 66824 已清理。执行 MSBuild 的 fne_release|Win32 构建，退出码为 0，产物为 bin/fne_release/AutoLinker.fne。未将该产物覆盖到用户 IDE 安装目录。


## 内容恢复的最终入口选择（后续修正）

完整 0x46B310 适用于“打开/重载工程”，不能单凭 ABI 和正向加载测试认定满足“原工程身份不变”的恢复。生产内容恢复改为重现其中的二进制分支：0x46B010 -> 0x46B4D0 -> 恢复原身份 -> 0x46D0C0 -> 0x46D3C0。原身份在整个恢复事务之前捕获，失败回滚使用同一份。详见 backup-restore-validation.md 的最终修复章节与 PID 50464 的真实 WebView2 测试证据。早期分支调查和旧探针输出仅代表当时实验，不作为最终代码已验证的依据。
